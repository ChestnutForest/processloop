# NFR-DATA-001 記録したデータを永続化して再起動後も参照できるようにする

## 要求

利用者が階層と時間ログを記録すると、その内容を記憶装置に書き出し、
アプリケーションを終了しても内容を保ち、次回の起動時に読み出して、
記録した時点と同じ状態を復元する。

<!-- 動詞: 記録する / 書き出す / 保つ / 読み出す / 復元する = 5個 -->

## 理由

PSP は日々の作業を継続して記録し、蓄積したデータから見積りと品質を改善する方法論である。
**記録が失われれば方法論そのものが成立しない**。

とりわけ PROBE は過去の見積りと実績の組に回帰分析をかけるため、
数か月にわたる蓄積を前提とする。1回の起動で失われるデータには意味がない。

移植元がファイルに書き出す設計を採っているのも同じ理由による。

## 説明

### 保存先の選定

**SQLite を用い、Prisma 経由で操作する。**

| 候補 | 判断 |
|---|---|
| **SQLite** | ✅ 採用。個人利用に十分で、ファイル1つで完結する |
| ブラウザのストレージ | ❌ 容量制限があり、消去される恐れがある |
| 移植元と同じファイル形式 | ❌ 検索と集計に向かない |
| PostgreSQL などのサーバ型 | ❌ 個人利用には過剰。第2期で再検討 |

### 移植元との差異

| 項目 | 移植元 | 移植先 | 判断 |
|---|---|---|---|
| 階層 | `state`（XML の `<node>` 入れ子） | `HierarchyNode` テーブル | 検索と集計のため |
| 時間ログ | `timelog.xml`（全ノード分を1ファイル） | `TimeLogEntry` テーブル | 同上 |
| 欠陥ログ | `*.def`（ノードごとに連番） | `Defect` テーブル | 同上 |
| データ定義 | `*.dat`（ノードごとに連番） | ⚠️ M3 で設計 | 計算エンジンに依存するため |
| 既存データの移行 | — | **第1期では行わない** | 新規に使い始める前提 |

### 移植元のファイル形式との対応

第1.5期で移行機能を作る場合に必要となるため、対応関係を記録しておく。

| 移植元 | 形式 | 移植先 |
|---|---|---|
| `state` | XML。`<node>` の入れ子。属性11種 | `HierarchyNode` |
| `timelog.xml` | XML。`id` `path` `start` `delta` `interrupt` `comment` `flag` | `TimeLogEntry` |
| `*.def` | 旧はタブ区切り8項目、新は XML | `Defect` |
| `*.dat` | 連番。計算式を含む | ⚠️ M3 で設計 |

⚠️ **移植元は全データを `path`（階層パス）で結んでいる。** 移植先でも `path` を保持しつつ、
整合性のため外部キーでも結ぶ。

### データの範囲

| 項目 | 範囲 |
|---|---|
| データベースファイル | 1つ。既定の場所に置く |
| 同時に開くアプリケーション | 1つのみ（多重起動は想定しない） |
| 保存の契機 | 記録の確定時。定期保存は行わない |

### 保存の失敗時

| 状況 | 振る舞い |
|---|---|
| 書き込みに失敗した | 入力内容を保持したまま、再試行できる状態にする |
| データベースが破損している | 起動時に検知し、その旨を表示する |
| ファイルが存在しない | 初回起動として扱い、新規に作成する |

### スキーマの変更

第1期の途中でもエンティティの追加や属性の変更が生じる。
`Defect` は M2、`DataValue` は M3 で追加される。

**マイグレーションの仕組みを最初から用意する。** 後から導入すると、
それ以前に蓄積したデータの扱いに困る。

⚠️ ドッグフーディングにより **M1 完成の時点から実データが入る**。
この開発自体の記録が消えないよう、破壊的な変更には注意が要る。

## 仕様

### <データの書き出し>

- [ ] **NFR-DATA-001.10** 階層のノードを追加、変更、削除した時点で、内容を記憶装置に書き出す。
- [ ] **NFR-DATA-001.20** 時間ログを記録した時点で、内容を記憶装置に書き出す。
- [ ] **NFR-DATA-001.30** 書き出しに失敗した場合、入力内容を保持したまま、その旨を表示する。
- [ ] **NFR-DATA-001.40** 集計結果と派生指標は書き出さない。

### <内容の保持>

- [ ] **NFR-DATA-001.110** アプリケーションを終了しても、書き出した内容を保つ。
- [ ] **NFR-DATA-001.120** データベースを1つのファイルとして扱い、既定の場所に置く。
- [ ] **NFR-DATA-001.130** 保存した内容を、階層パスによって相互に参照できる形で保つ。

### <データの読み出し>

- [ ] **NFR-DATA-001.210** 起動時にデータベースを開き、記録済みの階層と時間ログを読み出す。
- [ ] **NFR-DATA-001.220** データベースのファイルが存在しない場合、新規に作成する。
- [ ] **NFR-DATA-001.230** データベースが破損している場合、その旨を表示し、記録の操作を受け付けない。

### <状態の復元>

- [ ] **NFR-DATA-001.310** 記録した階層の親子関係と並び順を、記録した時点と同じ状態で復元する。
- [ ] **NFR-DATA-001.320** 記録した時間ログを、対応する階層のノードに結び付けて復元する。
- [ ] **NFR-DATA-001.330** 計測中に終了した場合、その計測は記録されていないものとして扱う。

### <スキーマの変更への対応>

- [ ] **NFR-DATA-001.410** エンティティの追加と属性の変更を、蓄積済みのデータを保ったまま適用できるようにする。
- [ ] **NFR-DATA-001.420** 適用したスキーマの版を記録し、起動時に照合する。

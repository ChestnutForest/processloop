## 全体を通しての傾向

### プロンプトの性質による分類

| 分類 | 概数 | 例 |
|---|---|---|
| 調査・分析の依頼 | 約20件 | util分類、永続化調査、A-1〜E-4、カバレッジ |
| 実行結果の共有と確認依頼 | 約30件 | 各種 PowerShell 出力の貼り付け |
| 概念の解説依頼 | 約8件 | pnpm、巻き上げ、幽霊依存、ゴールデン |
| 方針の決定・選択 | 約10件 | 命名、スコープ、案A、submodule |
| 成果物の作成依頼 | 約10件 | スキル、zip、devlog、スライドプロンプト |

### プロジェクトの到達段階

```
スキル整備 → ライセンス調査 → 命名 → スキャフォールド → GitHub環境
  → NOTICE → スコープ確定 → ev分割 → 技術スタック → 環境構築
  → util分類 → 永続化調査 → A-1〜E-4の全調査 → カバレッジ確認
  → 機能整理 → ロードマップ → PSP/TSP対比
  → 第1段階zip → 配置・検証 → submodule検討
  → ★ステージ0-a実装（現在地）
```

### 特徴的な進め方

1. **実測を徹底** — 「調べてほしい」の依頼に対し、推測でなくソースを走査して数値を出す
2. **段階的な確認** — PowerShell の実行結果を細かく共有し、一歩ずつ確認しながら進む
3. **日次の資産化** — 区切りごとに devlog を生成し、NotebookLM に蓄積
4. **概念の都度確認** — 不明な用語（pnpm、幽霊依存、ゴールデン等）はその場で解説を求める
